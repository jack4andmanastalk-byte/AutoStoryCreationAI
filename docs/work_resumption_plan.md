# 創作作業の再開プラン

## 目的と前提

標準フロー `scripts/story_project.py` を使い、題材と制約から読める原稿を1本作り、実際の摩擦を次の改善につなげる。[標準フロー](standard_flow.md)と[実用改善ロードマップ](practical_roadmap.md)に沿う。これは計画であり、実走はまだ開始していない。

実行は Arena のエージェントが担当し、作業状態の正本は GitHub の作業ブランチに置く。利用者は題材・条件を決め、開始と作品の採用を判断する。実験用の二段階フローは標準経路と混同しない。

## 着手順

| 順 | 作業 | 完了の目安 |
| --- | --- | --- |
| 1 | **創作条件の確定** | 題名、題材・premise、章数、章ごとの目標字数、必要な制約を決定する。既存作品を続ける場合は作品IDと対象リビジョンを指定する |
| 2 | **保存と実行の準備** | `works/<project-id>` を使い、既存作品の上書きを避ける。`python scripts/check_persistent_paths.py works/<project-id>` で保存先を確認し、ブランチ・入力・変更状況を点検する |
| 3 | **標準フローの実行** | `init` → `run` → `relay status` / `relay submit` で plan、8設計、本文を進める。要求ごとに実際の応答だけを記録し、回答済み応答を再生成しない |
| 4 | **節目で保存・再開** | 応答待ち、応答の取り込み、完了の各節目で project 状態と relay を揃え、内容・権利・秘密・容量を確認し、作業ブランチに commit / push する。push が失敗した場合は保存済みとせず停止する |
| 5 | **原稿と状態の確認** | `doctor` と `summary` で状態・警告を確認し、`render --out` と `render --reader` で正本と読書用原稿を作る。本文を読み、未解決事項と修正候補を記録する |
| 6 | **次の改善を1件選ぶ** | 完走を妨げる摩擦を優先し、実例・変更内容・回帰テスト・次の作品での確認方法を記録する。必要なら `revise` または `continue` を使う |

手順とコマンドの詳細は [quickstart](quickstart.md) と [Arena運用手順](arena_operation.md)を参照する。`relay status` の exit 3 は回答待ち、0 は完了・待機なし、2 は失敗である。保存先の事前検査は GitHub への保存を保証しない。

## 完了時に残すもの

- 題材と制約、生成・修復・待機の回数、応答の出所。
- 作品の状態、relay、設計、正本の原稿、読書用原稿、`summary` と `doctor` の結果。
- 人が読んだ所見、残った blocker / warning / observation、次の改善1件。
- 保存したブランチとコミット。機密や大容量データは通常の Git ファイルとして無条件に保存しない。

`clean` や `pass` は検査した範囲の状態であり、物語の品質を保証しない。質の評価は原稿を読んで行う。

## 次の開始判断

新規作品の題名・題材・章数・章ごとの目標字数を指定するか、続ける既存作品のIDと目的を指定する。指定後にエージェントが保存先を確認して着手する。
