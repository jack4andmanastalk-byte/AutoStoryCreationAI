# 実作業を始めるための開始プロンプト

新しい Arena チャットで、このリポジトリの実用改善を続けるための開始文です。
通常は、下のコードブロック全体を新しいチャットの最初のメッセージとして使います。

```text
このリポジトリで、AIによる自動創作の実用改善を進めてください。

まず次を読んでください。
- docs/practical_roadmap.md
- docs/arena_operation.md
- 必要に応じて docs/project.md、docs/two_stage_slice.md、README.md の関連箇所

前提:
- このリポジトリの目的は、AIによる自動創作活動そのものです。AIが題材や条件から、世界・歴史・人物・関係・物語構造・場面・文体・本文を作り、検査と修復を経て、続き・改訂・分岐・編纂を続けられるようにしてください。
- 人間の役割は、題材と制約の指定、生成の開始、採用判断、読後フィードバックです。開始後の創作段はAIが進め、人間が本文を代筆したり成果物を手作業で運んだりすることを標準にしないでください。
- 厳密な検証、率、再発率、因果効果よりも、実際に作品を作り、読み、摩擦を直す実用改善を優先してください。
- 実行は Arena Agent Mode と GitHub で完結させてください。ローカル実行を前提にしないでください。
- 実モデルの応答を捏造しないでください。生成が必要な場合は、このセッション内で実際に生成した応答だけを relay 方式で逐語的に取り込んでください。生成プロンプト本文はチャットに表示しないでください。
- L2/L3 は frozen_not_measured のままにし、品質・面白さの主張をしないでください。
- 過去の事前登録、results.json、完了した run と relay は書き換え・削除しないでください。
- 現在のセッションブランチで作業し、指示があるまでマージしないでください。

今回の作業:
docs/practical_roadmap.md の U-01 から始めてください。

具体的には、まず既存の入口（創作project、run_pipeline、二段階方式）を調査し、AI自動創作の標準フローを一つに決めるための最小実装と quickstart を進めてください。単なる説明で終わらせず、コード・文書・テストの変更として実作業を進めてください。

進め方:
1. 現状の入口と責務を短く把握する。
2. 標準フローの決定に必要な最小変更を行う。
3. 題材と条件から3章の原稿まで進める標準手順を、Arena内で使える形にする。
4. 可能なら scripted または実応答の最小作例で導線を確認し、摩擦を記録する。
5. テストを実行し、コミット、push、PR作成まで行う。マージはしない。
6. 最後に、何を決め、何を実装し、次に U-02 へ進むために何が残ったかを日本語で報告する。

判断が必要な場合でも、まずリポジトリ内の既存方針と実装から決めてください。本当に利用者の判断が必要な場合だけ質問してください。
```
