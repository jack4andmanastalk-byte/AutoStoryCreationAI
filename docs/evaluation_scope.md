# 評価の運用範囲 — L1-only / L2・L3 凍結

- 決定日: 2026-10-24
- 機械可読な状態: [`configs/evaluation_scope.yaml`](../configs/evaluation_scope.yaml)
- 対象プロトコル: [`protocol-v1`](protocol.md)（**本文と G1–G5 は変更しない**）

## 決定

現在の研究運用は **Arena.ai だけを生成経路とし、L1（決定論的検査）を対象**にする。
独立したモデル判定器を用意できず、人間の評定も実施できないため、**L2（モデル判定）と
L3（人間評価）の実証・較正・追加開発を凍結する**。

凍結は、L2/L3 を「不要になった」「合格した」と判断することではない。測定できない層を
測ったかのように扱わないための運用停止である。

## 凍結するもの

* 実モデルによる L2 判定、その較正、外部ベンチマークとの較正
* 人間による L3 選好・識別・評定者間一致の測定
* 上記を目的にした新規の盲検ペア収集、判定プロンプト改良、較正機能の追加開発

既存のルーブリック、fixture、`judge_adapter.py`、`judge_pairs.py`、
`calibrate_judge.py`、`make_blind_pairs.py` とそのテストは、再現性と回帰防止のために
**凍結資産として保存する**。`make evaluate` / `make calibrate` は固定デモの再生には使えるが、
その出力を研究上の L2/L3 実証として使わない。

## 継続するもの

1. 13 スキルと S0–S3 の決定論的検査・配線の保守
2. L1 の必須語、禁止パターン、継続性違反、監査カバレッジ、記述統計の測定
3. Arena の chat operator / relay を使った S0–S3 の探索的実験
4. 対照群の選定・凍結（L1 の G2 にも使用。G3/G4 の実施を意味しない）
5. L1 の失敗類型を根拠に、スキル・プロンプト・パイプラインを一つずつ変更して再測定

## 報告の制約

* **G3/G4 は `frozen_not_measured`**。未達とも合格とも記録しない。
* Arena のモデル版を固定できない運用では **G5 を主張しない**。したがって G1/G2 を含む
  L1 の値も、protocol-v1 の合格証拠ではなく **探索的な参考値**として報告する。
* 「作品の質が向上した」「人間に近い」「protocol-v1 の意味で機能している」とは言わない。
  言えるのは「この L1 指標が、記録した条件間でどう変わったか」だけである。
* L1 は意味的な面白さ、独自性、感情効果を測らない。構造検査の通過を作品品質の証明にしない。
* 新しい実験の `results.json` には評価範囲を記録し、`note.md` にも凍結と G5 の限界を残す。

## 再開条件

利用者が明示的に凍結を解除し、L2/L3 のそれぞれについて評定・較正に必要な条件を
整えた場合にだけ再開する。条件が整わないまま、L1 の結果を代替評価として格上げしない。
