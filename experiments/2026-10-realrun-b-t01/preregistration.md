## 誰が何をするか

このリポジトリは**モデルを呼ばない**。往復は arena.ai のチャット、状態は GitHub で完結させる。
**読者が端末を開くことは前提にしない。**

| 役 | すること | しないこと |
| --- | --- | --- |
| **ハーネス（エージェント）** | `scripts/` の実行、要求の書き出し、回答の取り込み、run・計測・コミット | 本文を書くこと |

| **人** | プロンプトを貼り、返ってきた回答をそのまま返す | 端末・`.venv`・コマンド入力 |

1 往復ごとに `relay/sample-1/requests/` と `responses/` がコミットされる。作業環境が消えても、
GitHub から同じ位置で再開できる。

## 何を決めたいのか

バッチ A（§21.1）は **Stage B だけ**を 3 標本走らせた。canon・設計・ログは固定で、書いたのは本文だけ。
その結果、次の 3 つが残った。

1. `fact_boundary`（「三年前」）は 3/3 の ch02 で、`character_boundary` は 2/3 で出た。どちらも修復で消えた。
2. 章の目安を割ったのは**修復後**の 2 章だけだった（修復前は目安内）。
3. 地名の観測（R1）は発火機会 0 で、採否の材料にならなかった。

バッチ B は、**同じ canon のまま、S1 の設計段から先を 1 標本ぶん通す**。目的は優劣の判定ではなく、
次の 3 点を記録することである。

1. **設計 8 文書は 1 試行目で通るか。** バッチ A の入力では `plot` / `scene` / `voice` の 3 つだけが
   与えられ、`brief` / `world` / `history` / `character` / `relation` は走っていない。
2. **設計を固定した効果と、方式の効果を切り分けられるか。** `2026-10-l1-pair-t01` は同じ canon・
   同じ設計で draft 段だけを比べた。その note の「次に試すこと」1 番目が本バッチの問いである。
3. **同じ canon で設計から書き直したとき、長さ・必須語・マーカーの現れ方が変わるか。**

| 観測器 | `--observe-surface` は使わない（S1 には無い機能） |

### なぜ plan を固定するのか

**canon は plan の成果物そのものである。** plan を走らせれば canon が変わり、「バッチ A と同一 canon」は
満たせない。`run_pipeline.py --canon` は「plan の代わりに既存 canon を使う」ための入口で、
`Makefile` の `design` 目標も同じ形（plan を 1 回走らせ、その canon を次の段に渡す）を取っている。

したがって本バッチが測るのは **S1 の design → draft** であり、**plan 段の出来は測らない**。
「S1 全体を測った」とは書かない。この trade-off は登録の時点で固定し、結果を見てから
「やはり S1 全体だった」と読み替えない。

> 参考: `2026-10-plot-ablation-t01/paired/` の `--prepare-shared` は、plan と設計 8 文書を
> 1 回だけ作って両腕で共有する。バッチ B はその「共有された plan」を、既存の canon
> （`t01` の共有 canon）で置き換えた形に当たる。走らせるのは設計から先である。

## 数え方（バッチ A の曖昧さをここで潰す）

バッチ A の R3 は「2 標本以上で**所見を出した**検査」とだけ書き、**最終報告だけを見るのか、
修復で消えた所見も数えるのか**を決めていなかった。本バッチは両方を出し、**片方を主に固定しない**。

| 数え方 | 設計 | 本文 | audit |
| --- | --- | --- | --- |
| `repair_erased_included` | `design/<doc>.report.json` の `first_attempt.findings` | `draft/<ch>-attempt-<n>.issues.txt` | `audit.json` |
| `final_only` | `design/<doc>.report.json` の `findings` | 採用章の所見（**構造上つねに 0**） | `audit.json` |

- **本文の所見は最終報告に残らない。** 採用されなかった試行の所見は `issues.txt` にしか残らず、
  `audit` は最終本文にだけ走る。したがって 2 つの数え方が違う値になるのは**設計段でだけ**である。
  この非対称は仕様であり、欠陥として扱わない（記録はする）。
- 長さの判定は**最終本文**で行う。`attempt 1` の字数は「書いた時点で外れていたか、修復で外れたか」の
  切り分けにだけ使い、判定を二重に作らない。

## 判定規則（結果を見る前に固定）

### B1: 設計 8 文書の 1 試行目

| 結果 | 判定 | その後の行動 |
| --- | --- | --- |
| 8 文書すべて 1 試行目で所見 0 | `design_clean_first_attempt` | 設計は律速でない。本文側の規則（B2・B4・B5）を見る |
| 1 試行目に所見があり、修復で解消 | `design_repaired` | 落ちた `check` を列挙し、次の修正対象の候補にする |
| 修復上限後も `unresolved` / `missing` | `design_unresolved` | どの文書か・どの検査かを列挙する。**本文の判定は続ける**（S1 は設計不合格でも draft へ進む） |

### B2: 章の長さ（目安 1,000〜1,400 字、3 章中 2 章以上）

| 結果 | 判定 | その後の行動 |
| --- | --- | --- |
| 2/3 以上が目安内 | `length_ok` | 目標値もプロンプトも動かさない |
| 目安外の章がすべて「attempt 1 は内・最終は外」 | `length_lost_in_repair` | 修復プロンプトに「字数を減らさない」を足す候補（実装はまだ） |
| 目安外の章がすべて「attempt 1 から外」 | `length_out_at_write` | draft プロンプトの目安を直す候補 |
| 両方がある | `length_mixed_causes` | 章ごとに原因を分けて記録する。判定は保留 |

**この規則はバッチ A の所見をそのまま引き継ぐ。** バッチ A では「目安を割る経路は修復にある」と
書いたが、標本は 3 つで、割れ幅も 183 / 15 / 187 字とばらついた。原因を章ごとに分ければ、
同じ結論が出るかを N=1 でも確かめられる。

なお、**目安を割った章が 1 つだけで 2/3 を満たす場合も、その章の原因は残す**
（`out_of_band_causes`）。判定は `length_ok` のままで、閾値は動かさない。判定が「合格」でも、
修復で長さが落ちた事実を消さないための措置である。

### B3: 繰り返す失敗（2 標本以上で同じ検査）

- `recurring`: 2 標本以上で同じ `check` が所見を出した（**数え方ごとに**判定する）。
- `no_recurring_failure`: どの `check` も 2 標本以上では出ない。
- `not_evaluable_at_n1`: 標本が 1 つで閾値に届かない。**判定しない。所見の一覧だけ出す。**

N=1 なので B3 は `not_evaluable_at_n1` になる見込みである。それでも規則を先に書くのは、
標本を足すときに**同じ規則で足せる**ようにするためである。

### B4: 必須語の完全一致

`灯台`・`鍵`・`嵐` が本文に**部分文字列として**出るか。`2026-10-arena-fresh-s1-n3` の seed 1 で
「嵐」が「暴風」になり `must_include_rate = 0.667` になった事例があるため、語形の言い換えは
**不一致**として数える。事後に語形を推論して合格へ書き換えない。

### B5: マーカーの宣言

最終本文の最初の `{{time: day=N}}` と `{{location: X}}` を canon の章 `day` / `location` と比べる。

| 結果 | 判定 |
| --- | --- |
| canon と食い違う宣言がある | `markers_disagree`（**S1 には照合する検査が無い**） |
| 食い違いは無いが、canon から補完した章がある | `markers_repaired` |
| 補完 0・食い違い 0 | `markers_declared` |

S1 の draft は、マーカーが無ければ canon から**補完して記録する**（黙って入れない）。
補完は「本文が書いていなかった」という事実であり、通過として数えない。

## 主張しないこと

- L2/L3（意味の整合・質）は `frozen_not_measured` のまま。G3/G4 は未測定、G5 は operator 方式では
  到達しない（同一 seed で同一出力を作れない）。
- N=1。**率・区間・有意差を出さない。**
- バッチ A との差を「S1 と二段階方式の効果」と呼ばない。canon は同じでも、N=1・同一 operator・
  プロンプトが別物である。
- **plan 段は測っていない。** 「S1 全体」とは呼ばない。
- 地名の観測（バッチ A の R1）は Stage B 専用の機能で、S1 では測らない。
- protocol-v1 の合格判定には使わない（探索的な参考値）。

## 打ち切りと失敗の扱い

1 標本が完走するか、修復上限で停止した時点で測る。**途中で結果を見て条件を変えない。**
本文が 2 試行とも不合格で `DraftError` になった場合も、そこまでの run を `sample-1/run` として残し、
判定は `incomplete` を出す。**止まった run を消して書き直さない。** 条件を変えてやり直す場合は、
走らせる前に別バッチとして登録する。
