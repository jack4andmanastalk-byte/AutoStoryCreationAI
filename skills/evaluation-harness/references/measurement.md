# 測定仕様 — 指標、バイアス統制、判定器プロトコル

## L1 決定論的検査

| 指標 | 定義 | 良し悪し |
| --- | --- | --- |
| `chars` | 空白を除いた文字数 | 記述のみ |
| `dialogue_ratio` | 鉤括弧内の文字数 ÷ 全体 | 記述のみ（作品の型で変わる） |
| `mean_paragraph_chars` | 段落あたりの平均文字数 | 記述のみ |
| `sentence_length_cv` | 文長の変動係数 | 記述のみ（低い＝単調、高い＝不揃い。どちらも質ではない） |
| `forbidden_per_10k_chars` | 禁止パターンの出現密度 | **低いほど良い** |
| `ced_per_10k_chars` | 継続性違反の密度（canon がある場合） | **低いほど良い** |

「記述のみ」の指標を失敗条件に使わない理由: 会話率が高い作品が良い作品ではない。
これらを点数にすると、評価が作品の型の好みに退化する。

### 欠陥密度（CED）

```
CED = 違反件数 ÷ 文字数 × 10,000
```

ConStory-Bench（ADD-01）の CED と同じ考え方（長さの影響を除く）だが、
**誤り類型も検出器も違うので、公表値と直接比較してはいけない**。
比較できるのは、同じ canon・同じマーカー運用で書かれた自分の作品同士だけ。

### 監査カバレッジ

マーカーのある章の割合。**カバレッジが違う 2 作品の CED は比較できない。**
マーカーの無い草稿は「矛盾が少ない」のではなく「検査されていない」。
差が 30 ポイントを超えると、ハーネスは CED 比較を `comparable: false` にして
`no_regression` の判定から外す。

### 禁止パターン

`harness/patterns.yaml` に正規表現で書く。決定論的で、根拠位置（ファイル・行）を出す。
増やすときは「なぜ禁止か」を `message_ja` に書く。理由の無いパターンは、
後から外せなくなる。

## L2 モデル判定

### 根拠の必須化

各次元は `evidence`（引用 `quote` または位置 `path`/`line`）を要求できる。
`evidence_required: true` の次元で根拠が空なら、その判定は `unevidenced` として
**ゲートを失敗させる**。根拠の無い点数は、測定のように見えるだけの意見である。

### 判定器のプロトコル

判定器は外部コマンドとして接続する。標準入力に 1 つの JSON、標準出力に 1 つの JSON。
ログは標準エラーに出す（標準出力に混ぜると解析できない）。

**採点**

```json
// 入力
{"mode": "score", "rubric": {"id": "...", "dimensions": [...]}, "story": "...", "context": {"story": "demo"}}
// 出力
{"dimensions": [
  {"dimension": "coherence", "score": 3,
   "evidence": [{"path": "ch03.md", "line": 3, "quote": "..."}],
   "rationale_ja": "..."}
]}
```

**ペア比較**

```json
// 入力
{"mode": "pairwise", "rubric": {...}, "a": "...", "b": "...", "context": {...}}
// 出力
{"winner": "a", "rationale_ja": "..."}
```

`winner` は `a` / `b` / `tie`。ハーネスは同じ組を A/B と B/A の 2 回呼び、
**同じ位置を選び続けたら順序バイアス**として引き分けに倒す。

### 記録すべきこと

比較を後から再現するために、判定器の名前・モデル・版・温度・プロンプトのハッシュを
残す。`judge` フィールドに名前が入る。外部コマンド側でログを保存すること。
**記録の無い L2 の比較は無効**とする。

### なぜ外部コマンドか

このリポジトリは API キーを持たない。判定器を内蔵すると、
依存と鍵がリポジトリに入る。外部コマンドなら、モデルの選択・更新・監査を
利用者側で管理でき、リポジトリはプロトコルだけを知っていればよい。

## L3 人間評価

ペア比較のラベルを JSON で渡す。

```json
{"items": [{"rater": "r1", "winner": "a"}, {"rater": "r2", "winner": "tie"}]}
```

出す値:

* `distribution` — a / b / tie の件数
* `agreement_with_judge` — L2 の勝者と一致した割合
* `warning_ja` — 評定者が 1 名なら「人間間の一致は測れない」

L2 の妥当性は L3 で測る。L3 が無い場合、L2 の点数は**較正されていない**と報告する。

### バイアス統制（LitBench, ADD-02 より）

| バイアス | 統制 |
| --- | --- |
| 位置（先に読んだ方が有利） | A/B・B/A の 2 回、不一致は引き分け |
| 長さ（長い方が良いと評価されやすい） | 文字数差 25% 超でペア比較を省略（解除は明示フラグ） |
| 評価者の属性 | L3 のラベルに評定者 ID を必須にし、1 名なら警告 |
| プロンプトの揺れ | 判定器の設定を記録し、比較は同一設定のみ |

## 失敗の類型化

| 欠陥 | 分類 | 担当 | 次の一手 |
| --- | --- | --- | --- |
| `dead_character_reappears` ほか整合性 | 整合性 | `skills/continuity-ledger` | 台帳と本文を直す |
| `forbidden_pattern` | 文体 | `skills/voice-style` | 言い換える／テンプレートを直す |
| 次元 `coherence` が低い | 質 | `skills/continuity-ledger` | 因果の欠落を特定 |
| 次元 `character_consistency` | 質 | `skills/character-core` | 人物表に戻す |
| 次元 `world_rule_consistency` | 質 | `skills/world-rules` | 規則とコストを書き直す |
| 次元 `originality` | 質 | `skills/premise-brief` | 企画段階で固有要素を足す |
| 次元 `reader_orientation` | 質 | `skills/scene-information` | 情報の提示順を直す |
| 次元 `prose_control` | 文体 | `skills/voice-style` | 文長・表記・視点を揃える |

チケットは `owner` ごとにまとめて出る。評価は数字ではなく**変更リスト**で終わる。

## 外部ベンチマークとの関係

| ベンチマーク | 何を借りたか | 何を借りなかったか |
| --- | --- | --- |
| ConStory-Bench | CED（密度）と誤り類型の考え方 | 19 類型そのもの（日本語作品に合わせていない） |
| LitBench | ペア比較・長さバイアス除去・報酬モデルによる較正 | 訓練済み報酬モデル（自前の判定器で代替） |
| NCP-Bench | 「事実台帳＋コミットメント」で長期対話を測る発想 | 100 環境のデータ |
| WSE-bench | 生成被覆・一貫性・豊穣さを分けること | 世界シミュレーション環境 |

**外部スコアを目標にしない。** 自前のパイプラインがどの類型で落ちるかを知るために使う。

## 既知の限界

1. L1 は canon に書いたことしか検査しない。書いていない矛盾は 0 件と表示される。
2. L2 の一致率は 8 割程度が上限（LitBench の最良で 78%）。人間の代替にしない。
3. ペア比較は「どちらが良いか」しか分からない。どこが悪いかは L1 とルーブリックで見る。
4. 文体の均質化指標は代理指標であり、作品の質を測らない。
5. 評価指標を変えると過去の結果と比較できなくなる。`rubric.version` を上げて別系列にする。
