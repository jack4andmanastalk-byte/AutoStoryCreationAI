## 1. 調査の位置づけ

公開資料によるスコーピング調査・実務カタログであり、事前登録したシステマティックレビューではない。検索エンジン結果の総数や、返された全候補を漏れなく保存した記録はない。以下のテーマは探索の整理と再探索用であり、全検索式・全検索履歴を厳密に再現したものではない。

### 代表的な探索テーマ

- game narrative pipeline / writing pipeline / narrative production
- game character development / DNA / character brief / casting / dialogue
- worldbuilding / environmental storytelling / lore / canon / historian
- narrative prototyping / demake / playtesting / narrative comprehension
- procedural narrative / character / history / authored content

- localization / line IDs / voice-over / captions
- 作品・会社名と上記語の組合せ、GDC公開スライド・公式ブログの参照先追跡

### 選定の優先順位

1. 米国制作組織の当事者による具体的な工程・道具・反復・失敗の説明。
2. 当事者への記名取材、講演の詳細な二次報告。
3. 方法の理解と限界のための学術研究、概念枠組み。
4. ツール仕様・専門職ガイド・非米国比較例。採用実態とは区別。
5. 索引・告知は出典の同定に限定。本文未確認を補わない。

## 5. コーディングと統合

- source IDは資料単位、practice IDは実務テーマ単位。両者は多対多。
- `domains`は比較用の関心タグで、著者が使用した正式分類とは限らない。
- PDCA/PDSAは本報告による分析枠。会社自身の用語採用とは別。
- 本文中で「推奨」「本稿の設計案」「参照モデル」とした図・schema・チェックリストは統合的提案。
- 開発者の自己報告と独立評価、ツールの能力と企業による採用、計画と実施を分ける。
- 同じ作品・発表の資料を独立した標本に数えない。55件から採用率は推定しない。
- 地域は制作側の関係で判定。Ubisoft Montreal、海外研究、ink仕様等を米国導入の証拠にはしない。
- real historyの研究手順と、fictional history／canonの内的整合を分ける。
- 生成された文法・条件選択から、LLMの採否を推定しない。

## 6. 検証の範囲

`validate.py`でオフライン検証するもの：

- UTF-8／JSONL／JSON Schema、61資料・42実務、IDの一意性。
- 55／3／3の区分、確認範囲の集計。
- source↔practiceの相互参照、本文の脚注・実務ID。
- ISO形式の日付精度、日付順序、URL形状、ハッシュ形状。
- 特に重要な要旨・索引・ブロック応答・Steam公開日の扱い。

検証しないもの：全外部URLの現時点での稼働、全主張の第三者による再読、因果関係、業界全体の網羅性、著者発言の真実性。スクリプトが成功してもこれらは保証されない。
