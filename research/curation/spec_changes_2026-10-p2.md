# 仕様変更ノート — seed-01/02/03/09/10 を executable へ引き上げた条件

- 日付: 2026-10-24
- 対象: `seed-01-premise-brief`、`seed-02-world-rules`、`seed-03-history-timeline`、
  `seed-09-voice-style`、`seed-10-revision-loop`
- 契機: seed-08/13 と同じく、参照技法の多くが `partial`（合格条件の欠落）だった。
  5 seed が引く 78 件のうち `executable` は 10 件、`partial` は 62 件、
  `reference_only` は 6 件（`research/catalog/executability.jsonl`）。
- 変更の性格: **実装上の追加と設計変更**。原典の処方をそのまま手順化したのではなく、
  「何をもって合格とするか」を本リポジトリが書き下ろした（`mapping_authorship: editorial`）。
  前回（seed-08/13）と同様、**カタログは変更せず**、
  `research/program/skill_seeds.jsonl` に `status: implemented` と
  `acceptance_written` / `implementation` を追加した。

## 1. 共通の決定（5 スキル共通）

| # | 決定 | 理由 |
| --- | --- | --- |
| 1 | 検査できるのは**構造**だけ。質の判定は L2/L3 に回す | 5 seed の `partial` の欠落はすべて合格条件であり、質の合格条件は手元の材料では閉じない |
| 2 | 重要度に **high を使わない**（seed-10 の批評は由来の重要度を継承） | 設計書の欠陥は「矛盾」ではなく「検証不能・拘束の弱さ」。本文の破綻と重みが違う |
| 3 | 不足は **skipped ＋ 理由**（canon・サンプル・禁止表現の欠落時） | 空の入力で「所見 0 件」と表示するのが最悪の失敗（seed-08 の決定 4 と同じ） |
| 4 | 未定は「未定」と明示すれば許容し、空欄は所見にする | 分からないことと書いていないことの区別が、後工程の信頼になる |
| 5 | CLI の終了コードは 0/1/2（`audit_continuity.py` と同じ） | CI に載せるため。`--fail-on` の既定は `medium` |

## 2. seed-01 premise-brief の変更点

| # | 決定 | 理由 |
| --- | --- | --- |
| 1 | 四要素（誰・どこ・望み・妨げ）を宣言させ、ログラインとの一致を検査する | 「一文で書く」だけでは検証不能。部品表との照合にした |
| 2 | ログラインは一文・20〜300 字 | 字数は目安であり、質の基準ではないことを明記 |
| 3 | 主題は対立の印（対・vs・⇔）の有無で判定する | 対立の深さは見ない。形だけを見る |
| 4 | 類似作は 3 件・軸・10 字以上の差分説明を必須にする | 題名の列挙を差分の説明に変えるため |
| 5 | 禁止条件には `check_ja`（確認方法）を必須にする | 確認方法のない禁止は守れない |

## 3. seed-02 world-rules の変更点

| # | 決定 | 理由 |
| --- | --- | --- |
| 1 | コストを必須にする（5 字以上） | 代償なき力は物語を壊す。コストの妥当性は見ない |
| 2 | 例外には条件を必須にする | 無条件の例外は抜け道になる |
| 3 | 地理は canon の場所 ID と完全一致で照合する | 表記揺れを許すと照合が検証不能になる |
| 4 | 本文中の規則違反は検査しない | 世界ファイルと本文の照合は意味理解が要る。L2 に回した |

## 4. seed-03 history-timeline の変更点

| # | 決定 | 理由 |
| --- | --- | --- |
| 1 | 年表は年代順の並びを必須にする | 循環史観は対象外と明示した（検査と相容れない） |
| 2 | 由来を invented / adapted / cited に分け、`cited` には書誌情報を必須にする | 実在史料の権威を創作に借りないため |
| 3 | 知識地図は既知と未知の重なりを検査する | 人物の知識状態を canon と接続するため |
| 4 | 実在史の考証は範囲外とする | 混交の防止（由来区分）に留めた |

## 5. seed-09 voice-style の変更点

| # | 決定 | 理由 |
| --- | --- | --- |
| 1 | パターン所見は **medium 上限**、乖離は **low**。high を出さない | 日本語の省略・倒置のため、正規表現の一致は断定にならない |
| 2 | 台詞とマーカーは検査対象外にする | 語り手の断定は地の文に現れる |
| 3 | 視点人物自身の内面は許容する（名前・別名・自称で除外） | 一人称の「私は思った」は正当なため |
| 4 | 乖離（2 倍・0.3）は注意喚起に留め、失敗条件にしない | 文体の均質化は個性を失わせる（seed の `risks_ja`） |
| 5 | 33 件の参照技法のうち 11 件だけを検査に使う | 残り 22 件は背景知識であり、検査条件に落とせる形ではなかった |

## 6. seed-10 revision-loop の変更点

| # | 決定 | 理由 |
| --- | --- | --- |
| 1 | ループを plan→apply→compare の 3 手順に分け、CLI で分離する | 一括実行では「何が直ったか」が辿れない |
| 2 | パッチは anchor の正確な一致を要求し、曖昧さを失敗にする | 推測で当てると、直した箇所が分からなくなる |
| 3 | 前後比較は（由来・種別・対象・章）の同一性で数える | 文面が変わっても対象が同じなら残存 |
| 4 | 2 ラウンド連続の残存を根本原因の疑いとして報告する | 三度目の局所修正を止め、設計に戻す合図 |
| 5 | S2（改稿）は監査由来の批評だけを直す。文体の好みで書き換えない | 改稿の効果と文体変更を分離するため（S3 が文体を担当） |
