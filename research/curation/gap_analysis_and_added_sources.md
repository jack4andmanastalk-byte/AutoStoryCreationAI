## 1. なぜ追加調査が必要だったか

添付コーパスは **「人間の創作論・制作実務のカタログ」** としては充実している。
しかし、本リポジトリの目的である **AI による自動創作の研究と、スキル／ハーネス／パイプラインの改善**
に必要な次の層が丸ごと欠けていた。

| # | 欠けていた層 | コーパスの状態 | 帰結 |
| --- | --- | --- | --- |
| G1 | **AI 生成物の評価** | 評価ベンチマークが 0 件。 | 「良くなったか」を測れない。 |
| G2 | **長編生成のパイプライン** | Re3 以前の創作論のみ。 | 計画→執筆→改稿の実装知がない。 |
| G3 | **スキルの規格** | 79 ツールの紹介はあるが、共通仕様がない。 | スキルを移植可能な形にできない。 |
| G4 | **評価ハーネスの実装** | PDCA の概念図のみ。 | ルーブリックを CI に載せられない。 |
| G5 | **日本語圏の実証** | 日本語の創作論は多いが、AI との協働研究がない。 | 英語のベンチマークをそのまま適用する危険。 |

追加調査は、この 5 層を**最小限の一次資料で埋める**ことを目的とした。

## 2. 方法

### 2.1 検索

* クエリ: 12 本（英語 8・日本語 4）。主なもの:
  * `LLM story generation survey 2025 2026 long-form narrative consistency benchmark`
  * `LitBench Re3 DOC story generation evaluation benchmark LLM creative writing`
  * `Anthropic Agent Skills SKILL.md specification progressive disclosure 2026`
  * `LLM creative writing evaluation harness rubric promptfoo inspect AI agent evaluation framework`
  * `Re3 recursive reprompting revision DOC detailed outline control StoryWriter agent framework`
  * `日本語 生成AI 小説 創作 研究 評価 一貫性 2026`
* 取得: 検索結果のスニペットに加え、主要論文の arXiv メタデータ、Agent Skills 仕様、
  評価ツールの公式ドキュメントを直接取得。
* 選定基準:
  1. 一次資料（論文・仕様・公式ドキュメント）を優先。
  2. 2025–2026 のもの。古典（Re3/DOC）は系譜として例外的に採用。
  3. 数値主張は、取得できた範囲の要旨・結果表に限定。本文全体を読んでいない場合は明記。
  4. 二次ブログ・報道は、日本語圏の実践・文脈の証拠としてのみ採用し、`type` で区別。

### 2.2 証拠水準の扱い

`added_sources.jsonl` の `verification` に、何を確認したかを記録した。

* `abstract and arXiv metadata fetched` … 論文要旨と書誌を直接確認。
* `search result excerpt` … 検索結果の抜粋のみ。原典の該当頁は未確認。
* `documentation page fetched` … 仕様・ドキュメントを直接確認。

**査読済み・プレプリント・仕様・ブログ・報道を同一の「証拠」として扱わない。**

## 3. 追加した資料（要約）

### G1. 評価ベンチマーク

| 資料 | 何を測るか | 主要な数値 | 使いどころ |
| --- | --- | --- | --- |
| **ConStory-Bench**（Li et al. 2026, ACL Findings / arXiv:2603.05890） | 長編の整合性。5 カテゴリ 19  subtype。CED（1 万語あたり誤り密度）と GRR。 | 2,000 プロンプト。最良 GPT-5-Reasoning でも CED 0.113。自動検査器 F1 0.678（人間専門家 0.281）。 | 継続性台帳の外部基準。誤り類型のタクソノミー。 |
| **LitBench**（Fein et al. 2025, EACL 2026 / arXiv:2507.00769） | 短編の人間選好。ペア比較。 | テスト 2,480 組、学習 43,827 組。ゼロショット最良 73%、学習済み報酬モデル 78%。 | 選好評価の上限とバイアス統制（長さ・時間・人気）。 |
| **NCP-Bench**（Ma et al. 2026, ICML / arXiv:2608.08160） | インタラクティブ物語の長期コミットメント保持。 | 100 環境。GPT-5.2 でも 20 ターン生存 42%、事実衝突 40–68%。 | 分岐・対話型パイプラインの検査項目。 |
| **WSE-bench**（arXiv:2608.15654） | 生成被覆（Generation Coverage）・正典的一貫性（Consistency）・豊穣さ（Richness）のプロセス評価。 | 一貫性と豊穣さのパレートフロンティアは非凹で、線形の重み付けでは選べない。モデル規模は持続生成だけを改善し、一貫性・発展には効きにくい。 | パイプラインの KPI 設計。 |
| **Text-to-Text Automatic Story Generation: A Survey**（EACL 2026 SRW 39） | 57 論文のレビュー。 | 一貫性・人物整合性・多様性・プロット制御・評価指標の不足を指摘。 | 評価指標を自作する際の出発点。 |

| 資料 | 構造 | 報告されている効果 | 使いどころ |

| **NstAgent**（2026, arXiv:2609.35759） | 人物・過去の出来事・将来要件を含む構造化ナラティブ状態の追跡（training-free）。 | 10K–100K 語で、長さが増えても整合性・品質が目立って劣化しないと報告。コード公開（`zhennan1/NstAgent`）。 | 台帳を外部状態として持つ設計の有効性。 |

### G3. スキルの規格

* **Agent Skills 仕様**（agentskills.io、2025-12-18 公開）:
  `SKILL.md` は YAML frontmatter（必須: `name` 1–64 字、`description` 1–1024 字）＋ Markdown。
  任意で `license`, `compatibility`, `metadata`, `allowed-tools`。3 段階の progressive disclosure
  （メタデータ約 100 トークン、本文 5,000 トークン未満推奨、参照ファイルは必要時のみ）。
* **Anthropic Engineering** の設計解説、**arXiv:2602.12430** のサーベイ（仕様・取得・セキュリティ）。
* 影響: スキルは「巨大な創作論の塊」ではなく、**小さな手順＋必要なときだけ読む参照資料**に分解する。

## 4. 設計への含意（10 項目）

1. **整合性は「密度」で測る**。総数ではなく 1 万語あたりの誤り密度（CED）にすると、
   長さの異なる作品を比較できる（ConStory-Bench）。
2. **短編の質はペア比較で測る**。絶対点（1–10）は評価者間で揺れる。LitBench 型の
   ペア比較＋報酬モデルが安定する。
3. **LLM 判定は人間判定の代替にならない**。最良でも一致率 78%。判定器の精度を定期的に較正する。
4. **長さ・順序・人気のバイアスを統制する**。LitBench は長さバイアスを除かないと
   報酬モデルが長い作品を好むことを示す。プロンプトの A/B 順序も入れ替える。
5. **計画の粒度が長編の一貫性を決める**。DOC の +22.5pt は、アウトラインの詳細化と
   生成時制御の両方が寄与している。
6. **状態は会話の外に置く**。NstAgent は人物・過去・将来要件を構造化状態として追跡する。
   LLM のコンテキストに頼らない。
7. **インタラクティブ作品は「事実台帳＋コミットメント」で検査する**。NCP-Bench の
   20 ターン生存率 42% は、通常の文章評価では見えない失敗を示す。
8. **プロセスも評価する**。WSE-bench の生成被覆・一貫性・豊穣さは、
   最終テキストだけでは見えないパイプラインの弱点を示す。
9. **スキルは小さく、参照は外に置く**。Agent Skills の progressive disclosure に従い、
   `SKILL.md` は 5,000 トークン未満、詳細は `references/` へ。
10. **日本語の均質化を測る**。表記・読点・文長・語彙の分布を生成前後で比較する
    （三浦 2026）。英語の文体指標をそのまま移植しない。

## 5. 追加しなかったもの

* **WritingBench / LongStoryEval の原典**: NstAgent の記述から存在は確認したが、
  書誌・URL を直接確認できなかったため、独立レコードにしていない。次回の検索対象。
* **EQ-Bench Creative Writing / Japanese-RP-Bench**: 二次ブログでのみ確認。
  リーダーボードの一次 URL と評価方法を確認してから追加する。
* **有料の商用モデル比較**: 再現性・費用の観点から、公開ベンチマークの結果を参照する方針。
* **小説投稿サイトの利用規約・著作権の詳細**: 既存の [`../../docs/legal_and_ethics.md`](../../docs/legal_and_ethics.md)
  の範囲を超えるため、別タスクとする。

## 6. 再検索のトリガー

次のいずれかが起きたら、この追加調査を更新する。

* 新しい長編生成ベンチマーク（ConStory-Bench の後継、日本語版）が公開された。
* Agent Skills 仕様の改訂（`allowed-tools` の標準化など）。
* 主要モデルの世代交代（評価結果の陳腐化）。
* スキル／ハーネスの実装で、既存の指標が判別力を失った。
* 日本語の商用作品・同人作品に関する実証研究が公開された。
